# Portfolio Script Structure

이 저장소는 실제 게임 개발용 전체 프로젝트를 그대로 공개한 형태가 아니라, 포트폴리오용으로 정리된 코드 스냅샷입니다.

핵심 메시지는 다음과 같습니다.

- 전체 프로덕션 리포지토리 전체를 공개하는 것이 아니라, 코드 리뷰를 위해 핵심 구조만 정리한 형태입니다.
- 보안상 민감한 정보, 개발용 설정, 비공개 자산, 임시 테스트 코드를 제거했습니다.
- 게임 로직, 데이터 구조, 외부 서비스 연동, UI 흐름이 어떤 역할을 하는지 한눈에 보이도록 폴더를 정리했습니다.
- 이 구조는 실제 게임 프로젝트를 설명하기 위한 포트폴리오 정리본이며, 코드 탐색성과 가독성을 우선적으로 고려했습니다.

## 프로젝트 의도

이 코드는 단순히 파일을 나열한 형태가 아니라, 게임 설계와 구현 구조를 포트폴리오 관점에서 보이도록 정리한 것입니다.

검토자가 이 저장소를 볼 때 다음을 이해할 수 있도록 구성했습니다.

- 어떤 영역이 게임 로직인지
- 어떤 영역이 데이터 계층인지
- 어떤 영역이 외부 연동인지
- 어떤 부분이 UI 및 화면 제어인지
- 어떤 부분이 공통 재사용 코드인지

즉, 이 저장소는 “실제 게임 전체 코드”보다 “설명 가능한 구현 구조”에 더 가깝습니다.

## 1. App
- 게임의 전역 초기화, 메인 흐름 관리, 설정 값, 주요 런타임 제어를 담는 영역입니다.
- 씬 전환, 게임 상태, 기본 설정, 핵심 관리 객체들이 위치합니다.
- 대표 예시: MainManager, Config, Player, Option, UISetManager, TreasureManager

## 2. Gameplay
- 실제 플레이 경험을 구성하는 핵심 도메인 로직을 담는 영역입니다.
- 카드, 전투, 캐릭터, 적, 스테이지, 스토리 흐름을 역할별로 분리했습니다.

### Gameplay/Battle
- 전투 진행, 턴 흐름, 액션 처리, 전투 관련 함수 모델을 포함합니다.

### Gameplay/Cards
- 카드 데이터 정의, 카드 배치 계산, 카드 구성 요소를 관리합니다.

### Gameplay/CardSystem
- 카드 효과, 조건 분기, 장비/효과 처리와 같은 카드 동작 로직을 포함합니다.

### Gameplay/Characters
- 캐릭터 상태, 이동, 행동 로직과 관련된 구현을 담습니다.

### Gameplay/Enemies
- 적의 행동, AI, 스킬 및 전투 로직을 담습니다.

### Gameplay/Stage
- 스테이지 진행, 맵 이동, 진행 제어와 관련한 로직을 포함합니다.

### Gameplay/Story
- 스토리 흐름, 이벤트 진행 및 narrative 관련 처리를 담습니다.

## 3. Data
- 게임에서 사용하는 데이터 구조와 데이터 계층을 정리한 영역입니다.
- DTO, DAO, Entity, Mapper, Model, ScriptableObject 계층이 명확히 분리되어 있습니다.

### Data/GameData
- 게임 상태, 저장 데이터, 전역 상태 관리와 관련된 데이터 구조를 담습니다.

### Data/DTOs
- 외부 데이터나 서버 응답을 전달하는 데이터 객체를 포함합니다.

### Data/DAOs
- 데이터 접근 계층으로, 저장소 및 데이터 조회 로직을 담당합니다.

### Data/Entities
- 도메인 엔티티와 핵심 게임 객체 모델을 포함합니다.

### Data/Mapper
- 서로 다른 모델 간 변환 로직을 담당합니다.

### Data/Models
- 기능적으로 필요한 모델과 상태 구조를 정의합니다.

### Data/SO
- ScriptableObject 기반 데이터 정의를 담습니다.

## 4. Services
- 외부 API, 서버, 데이터 소스 연동 영역입니다.
- 인증, 세션 관리, 외부 데이터 로딩, 서버 커넥션 및 데이터 수집 로직이 위치합니다.

### Services/Supabase
- 로그인, 세션 유지, 서버 데이터 통신과 같은 연동 로직을 포함합니다.
- 공개용 포트폴리오 환경에서는 민감 값이 비워지거나 placeholder 상태로 유지됩니다.

### Services/DataLoaders
- Google Sheets, CSV 등 외부 데이터를 불러오는 로더를 포함합니다.

## 5. UI
- 화면 구성, 입력 처리, 사용자 인터랙션을 담당하는 영역입니다.

### UI/Controls
- 버튼, 입력 이벤트, 화면 제어와 관련된 로직이 포함됩니다.

### UI/Monobehaviors
- UI 오브젝트와 연결되는 MonoBehaviour 기반 컴포넌트를 정리합니다.

### UI/Popups
- 팝업, 알림, 모달 UI와 관련된 동작을 담습니다.

## 6. Shared
- 여러 모듈에서 재사용하는 공통 코드가 위치하는 영역입니다.

### Shared/Generics
- 범용 제네릭 구조와 재사용 가능한 기본 설계를 포함합니다.

### Shared/Utils
- 공통 유틸리티, 보조 함수, 반복적으로 사용되는 헬퍼 로직을 담습니다.

## 7. Development
- 실험용 코드, 튜토리얼, 비핵심 프로토타입을 분리해 놓은 영역입니다.

### Development/Tutorial
- 튜토리얼 흐름과 교육용 시퀀스 로직을 포함합니다.

## 정리 목적
이 구조는 다음 기준으로 재구성되었습니다.

- 게임 로직과 앱 부트스트래핑을 분리
- 데이터 계층과 런타임 로직을 분리
- 외부 API 및 백엔드 의존성을 Services로 통합
- UI, 공통 유틸, 실험 코드를 독립 영역으로 분리
- 공개용 포트폴리오에서 구조를 빠르게 이해할 수 있도록 정리

## 참고
- 보안상 민감한 값은 비워 두었고, 공개 저장소에 적합한 형태로 정리했습니다.
- 이 저장소는 실제 프로덕션 전체 코드가 아니라, 코드 리뷰와 포트폴리오 설명을 위한 정리본입니다.
- 폴더 구조를 통해 어떤 책임을 가진 코드인지 바로 파악할 수 있도록 구성했습니다.
